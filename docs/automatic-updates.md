# v0.1.3 自动更新

## 使用

先手动安装带独立更新器的 v0.1.3 完整程序包。在「设置与数据 → 程序更新」点击「检查更新」，阅读说明后下载。下载完成后勾选同意安装并重启，再点击安装。可开启每天一次的启动检查，默认关闭；不会自动下载或未经确认安装。

确认安装后等待已排队、处理中、自动重试的任务以及仍在生成的高分答案结束。等待期间可取消安装；正式进入安装后暂停页面操作及后台任务。程序退出后，独立更新器备份数据库、替换整个程序目录、重启并验证版本/页面服务/工作进程，再解除维护状态。录音、转写和知识库数据目录保持原位。

自动安装仅用于 Windows EXE 启动；源码启动可检查、下载，安装按钮不开放。程序与数据目录必须互不包含，程序目录的父目录需可写；没有写入权限时保留原程序，不自动申请管理员权限。请预留约 1–2 GB 可用空间，以容纳压缩包、解压文件和旧程序备份，实际随版本大小变化。

## 发布新版

统一修改 `interview_agent.__version__`，运行 `build-windows.ps1`。脚本测试后构建主程序和独立单文件更新器，再生成带逐文件哈希清单的版本包及 SHA-256 文件。发布 GitHub 正式 Release，标签为 `vX.Y.Z`，上传：

- `interview-agent-vX.Y.Z-windows-x64.zip`
- `interview-agent-vX.Y.Z-windows-x64.zip.sha256`

发布仓库固定为 `GloriousAndNew/interview-agent`。仅推送代码或标签不会提供可安装的新包；必须发布正式 Release 并附上附件。草稿、预发布、较旧版本及缺少对应 Windows 包的版本不会安装。不需要向安装者分发 GitHub Token。

检查采用 GitHub Releases API，下载前再次获取发布信息，优先使用附件的 SHA-256 digest，否则读取对应 `.sha256` 文件。只接受指定仓库的 HTTPS 下载链接及 GitHub 资源域名的重定向，不传递模型/OSS 密钥。参考 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

下载为后台线程，页面每 3 秒刷新进度；网络失败不影响面试处理。下载损坏或中断可重试（新版程序包下载从头开始，与录音 OSS 分片续传不同）。安装前校验 ZIP 大小与哈希，再检查内部平台/版本/文件哈希，拒绝越界路径、符号链接、重复路径和缺失文件。完整性校验不等同于发行者数字签名；本版未签名。

## 安装与失败恢复

独立更新器从数据目录运行，不占用待替换目录的运行库。正式安装前，主程序等待队列清空，使用维护标记与数据库事务拦截新任务和新高分答案生成，再退出所拥有的服务。更新器等待旧启动器退出，并取得启动器和 worker 的独占锁，避免与其他实例同时改动数据。

数据库先使用 SQLite Backup API 创建 `updates/database-before-update.db` 并校验。新程序复制至原程序父目录下的专用临时文件夹，再将旧目录重命名为备份目录、将新版目录移至原位置。重启沿用同一数据目录与端口；新版只有在版本/更新事务标识吻合、网页服务健康且工作进程已启动后，才解除维护状态并允许处理任务。

失败时先要求新版退出，确认服务锁已释放后恢复程序和数据库备份，自动重新启动旧版。若无法确认退出或文件仍被占用，保留维护状态、备份和诊断日志，不强制覆盖运行中的数据库。意外断电后，再启动 EXE 会尝试用独立更新器恢复未完成事务；若原程序路径暂时不存在，可运行数据目录中 `updates/helper-事务ID/interview-agent-updater.exe --plan 数据目录/updates/install-plan.json --recover` 恢复。请保留整个数据目录，必要时查看日志后人工处理。

保留的文件：

- 原程序父目录下 `.interview-agent-backup-事务ID`：更新前的整套程序。
- 数据目录 `updates/database-before-update.db`：最近一次更新前的数据库。
- 数据目录 `updates/install-plan.json`、`install-journal.json`：安装计划和恢复阶段。
- 数据目录 `logs/update-install.log`：独立更新器日志。

旧程序备份和下载缓存暂不自动删除，确认新版稳定后可在程序完全退出时手动整理，勿删除进行中事务的文件。普通启动失败可自动回退；更新已成功并解除维护后，不再自动回退，以免覆盖后续新增数据。

## 首次部署边界

v0.1.2 及更旧 EXE 没有自动更新入口，需要用户手动安装一次 v0.1.3。之后发布更高的正式版本即可走程序内更新。GitHub 访问失败时可继续手动下载完整包升级。正式发布状态与可下载附件以 [GitHub Releases](https://github.com/GloriousAndNew/interview-agent/releases) 为准，后续每次版本更新同步推送代码、发布正式 Release 和完整附件。
