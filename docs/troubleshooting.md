# 处理任务排查说明

处理链路：导入 → 音频预处理 → OSS 上传 → 阿里云转写 → 文本分批 → DeepSeek 整理 → 来源校验 → 入库 → 导出。DOCX、Markdown、TXT 和标准转写 JSON 跳过音频预处理、OSS 与转写。

## 查看进度与诊断

任务中心每 3 秒刷新阶段、批次、片段进度与耗时。展开“时间记录”查看提交、首次开始和结束时间；历时包含重试等待与暂停。历史记录缺少精确时间时明确显示估算或空值。

展开“处理链路与错误详情”查看阶段、批次、错误代码、尝试次数和调用记录。可下载不包含音频地址、密钥或模型回答正文的诊断 JSON。旧版任务缺少字段级记录时，无法事后恢复精确失败原因。

## 常见问题

| 阶段或错误 | 处理方式 |
| --- | --- |
| 音频预处理失败 | 检查文件是否存在、格式、FFmpeg、磁盘空间与写入权限 |
| OSS 上传或 ASR 失败 | 检查环境变量、区域、权限与网络，根据请求 ID 核对服务端任务 |
| 输出截断 | 程序自动拆分当前未完成批次，保留已完成结果 |
| OUTPUT_SCHEMA_INVALID | 模型字段不符合结构，程序反馈具体字段修复，仍失败时拆分 |
| INVALID_SOURCE_REFERENCE | 严格拒绝不允许的来源引用，自动修复或拆分；最终失败时核对对应批次 |
| 问题关联不合法 | 自动修复父引用与续接关系，不能通过时明确报告错误 |
| 附加建议被隔离 | 校对或角色建议不匹配原文，主结果可保存，需人工核对 |
| SEGMENTS_REQUIRE_REVIEW | 原文尚未可靠归入问答，详情中保留待核对片段 |
| 预算或恢复次数上限 | 先检查诊断，再决定调整预算或人工处理，避免盲目重试 |
| 保存或导出失败 | 检查本地磁盘、权限和文件占用，然后从检查点恢复 |

每个任务最多 64 次文本模型调用、12 次拆分、4 层拆分，并受月预算预留限制。手动重试保留已完成批次、来源记录和调用预算；远端任务提交状态不明时禁止自动重新提交。

“处理完成”表示可保存结果已入库，不代表语义全部正确。未归类原文、角色、校对建议和有疑义问答仍需人工核对。更换转写模型无法直接修复后续问答结构或来源校验问题。

## 本地记录与备份

数据目录可在“设置与数据”中查看。Windows 默认位于 `%LOCALAPPDATA%/InterviewAgent`，应用容器环境可能映射到对应物理目录。

- `app.db`：任务、问答、调用与事件。
- `jobs/<面试ID>/<任务ID>/attempts/<调用ID>.json`：本机模型最终响应，可能含面试正文。
- `transcripts/<转写ID>/`：提取原文，以及 DOCX/Markdown 的原始文档。
- `logs/worker.log`：后台日志。

完整迁移前先关闭程序，再复制整个数据目录。界面备份按钮只备份数据库。录音、原文、知识库、失败响应和密钥配置均不应提交到源码仓库。
